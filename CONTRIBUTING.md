# Contributing

Contributions are welcome when they make architecture decisions more explicit, verifiable, recoverable, or easier to execute.

## Before opening a pull request

1. Remove organization names, customer data, credentials, private URLs, production identifiers, and proprietary source code.
2. Keep `SKILL.md` concise; move detailed guidance into one-level references.
3. Write instructions in imperative form.
4. Run the Skill validator and test every changed script.
5. Explain the production failure or decision ambiguity the change addresses.

By contributing, you confirm that you have the right to submit the material under the MIT License.
